# Volna — на твоей волне

Музыкальное приложение для Windows и браузера: тёмный интерфейс с синими акцентами, аудиокаталог Internet Archive, персональная волна, избранное, плейлисты и офлайн-прослушивание разрешённых записей.

## Windows

Готовый файл: **`releases/Volna-1.3.1-Windows-x64.exe`**. Полностью закрой старую Volna и запусти новую сборку. Это portable-приложение Windows x64 со встроенным сервером; установка Node.js или права администратора не нужны. Сборка без цифровой подписи. Нативный запуск на Windows в облачной Linux-среде не проверяется.

Постоянный адрес `127.0.0.1:28741` сохраняет библиотеку между запусками. Сервер слушает только loopback. Окно работает с `sandbox`, `contextIsolation`, без Node.js в renderer. Системное меню отключено, чтобы Alt не перехватывал ввод при смене раскладки; при возврате фокуса в окно фокус передаётся странице.

## Аудиокаталог с версии 1.3.0

Основной поиск и «Моя волна» используют **Internet Archive / netlabels**: полные MP3 независимых артистов. Вход, cookies и API-ключи не требуются. Популярные коммерческие композиции могут отсутствовать; это не весь каталог Spotify или YouTube.

Поиск вверху показывает треки списком. «Загрузить ещё треки» продолжает обход релизов и страниц. Вкладка «В библиотеке» ищет среди сохранённых записей. Раздел «Каталог» позволяет искать релизы и открывать их целиком. Счётчики берутся у источника. Ошибки источника видны и позволяют повторить запрос.

Управление — в нижней аудиопанели: пауза, перемотка, громкость, предыдущий/следующий трек, повтор, случайный порядок, очередь, лайк и добавление в плейлист. Видео, iframe и обращения к YouTube API удалены. CSP запрещает фреймы.

Сохранённые ранее YouTube- и Яндекс-записи **не удаляются**: остаются названия, ссылки, избранное и плейлисты. Они помечены «Нет аудио»; значок поиска проверяет наличие в новом каталоге. Совпадения не гарантированы, неподтверждённая запись не подставляется автоматически. Эти метаданные не попадают в аудиоочередь и рекомендации. Если последним был YouTube-трек, нижний плеер начинает со встроенного доступного трека.

При сбое аудио плеер показывает постоянное сообщение с причиной, кнопками «Повторить» и «Копировать диагностику». Диагностика содержит версию, этап, код сети/HTTP и MediaError; адреса, cookies и секреты не включаются. Сервер хранит последние причины в памяти не более пяти минут. Быстрое переключение треков не показывает ошибку отменённого старого запроса.

## Рекомендации и коллекция

- Учитываются явно выбранные в поиске записи и музыкальный стиль поискового запроса, лайки, добавления в свои плейлисты, прослушивания, завершения и быстрые пропуски. Просто показанные результаты и исходные демонстрационные плейлисты не считаются выбором пользователя.
- Ранжирование учитывает жанры, теги и исполнителей, уменьшает повторы недавно прослушанного и чередует исполнителей. Это локальная модель, без подключения к алгоритмам Spotify или чужим аккаунтам.
- Волна сама находит до 12 новых треков за партию, исключает известные ID и берёт максимум две записи из релиза. Позиция поиска сохраняется. Обновление не прерывает текущую музыку; при трёх оставшихся открытиях очередь пополняется автоматически.
- При воспроизведении волны движутся синие частицы. Анимация останавливается на паузе и учитывает уменьшение движения в настройках системы.
- Новые избранные записи и добавления в плейлист появляются сверху. Старые списки мигрируют один раз с сохранением состава. Повторное воспроизведение не меняет порядок добавления. Вымышленного имени профиля нет.

Коллекция и предпочтения хранятся локально в `localStorage`; облачной синхронизации и серверных аккаунтов нет. Исходный демокаталог: восемь оригинальных стереотреков по 48 секунд с вымышленными исполнителями.

## Офлайн и импорт

Стрелка вниз рядом с треком сохраняет полный MP3 в IndexedDB, если источник указал распознаваемую лицензию Creative Commons или Public Domain. Для неизвестных условий скачивание недоступно. Есть прогресс, отмена, проверка полноты и атомарная запись; частичный файл не считается скачанным. «Скачанное» воспроизводит локальные Blob-копии без интернета и позволяет удалять их.

Копии привязаны к устройству и адресу приложения. Перенос HTML или очистка данных браузера не переносят сохранённую музыку. Восемь демотреков встроены в приложение и автономный HTML.

«Перенести библиотеку» читает CSV/JSON из Яндекс Музыки локально: названия, исполнителей, плейлисты и избранное. Поддерживаются русские и английские заголовки, BOM, запятая/точка с запятой/табуляция, кавычки, вложенные объекты API. Лимиты: 10 МБ и 10 000 записей. Повторный импорт объединяет данные; ошибки хранилища откатываются. Файлы только с ID отклоняются. Аудио и подписка Яндекса не переносятся; для импортированных названий доступен поиск в новом каталоге.

## Разработка

Требуется Node.js 20.19+ или 22.12+; облачная среда проверена на Node.js 24.

```sh
cd /workspace/Test-project
ELECTRON_SKIP_BINARY_DOWNLOAD=1 npm ci --cache /tmp/volna-npm-cache
npm run dev -- --port 5173 --strictPort
```

Dev слушает `0.0.0.0:5173`. Для production:

```sh
npm run export:html
npm run preview -- --port 4173 --strictPort
```

Vite dev/preview и Windows используют один `server/archive.mjs`: поиск, метаданные, изображения и Range-передача аудио через `/api/archive/*`. Браузер обращается к собственному серверу; в автономном HTML — непосредственно к Archive с его CORS. Канонические адреса аудио сохраняются в метаданных, поэтому старые офлайн-копии совместимы.

Сервер проверяет наличие MP3 в публичных метаданных релиза, приватность и ограничения. Каждый редирект ограничен HTTPS `archive.org` / `*.archive.org`; произвольные адреса, пути обхода и HTML вместо аудио отклоняются. Передача идёт потоком, поддерживает Range и отменяется при отключении клиента. Node сохраняет TLS и прокси среды; Windows использует `Electron net.request` с системными настройками сети, без cookies аккаунта. Адаптер возвращает события перенаправления шлюзу для проверки следующего адреса: `net.fetch` в Electron 44.7.2 отменяет ручные перенаправления с ошибкой `Redirect was cancelled`, из-за чего поиск в 1.3.0 работал, а MP3 не загружались. Нужны сетевые назначения `archive.org` и `*.archive.org`; зависимости устанавливаются с `registry.npmjs.org`.

Service worker сохраняет оболочку, шрифты, обложки и демотреки после первого успешного production-запуска. Динамические `/api/` запросы обходят его кэш. PWA устанавливается через браузер или боковую панель. Для новой облачной задачи процессы сервера запускаются заново.

## Автономный HTML и сборка EXE

`npm run export:html` создаёт **`exports/Volna.html`** со всеми стилями, скриптами, шрифтами, изображениями и восемью MP3. Открывается отдельным файлом; для онлайн-каталога нужен интернет. Ограниченный предпросмотр может запрещать скрипты или хранилище. Проверен запуск и аудио в sandbox с непрозрачным origin. `index.html` из исходников или `dist` по отдельности не является автономным приложением.

```sh
npm run release
```

Команда обновляет `releases/Volna.html`, `Volna.zip`, инструкцию и `SHA256SUMS`. `exports/`, `dist/` и `desktop-dist/` исключены из Git.

На Windows: `npm run release:windows`. В облачной Linux-среде:

```sh
npm run export:html
ELECTRON_BUILDER_CACHE=/tmp/volna-builder-cache CSC_IDENTITY_AUTO_DISCOVERY=false npx electron-builder --config electron-builder.json --config.electronDownload.cache=/tmp/volna-electron-cache --win portable --x64
python3 scripts/package_release.py --windows
```

Electron 44.7.2 и electron-builder 26.15.3 закреплены. Явный `electronDownload.cache` нужен для доступного `/tmp`; не изменяй HOME и не отключай TLS или проверку контрольных сумм. В EXE включены ru/en-US и уже собранный клиент. Файл хранится обычным Git blob ниже лимита 100 МиБ, без LFS. Перед публикацией проверяются соответствие ASAR сборке, AMD64 payload и запуск сервера из пакета; после публикации — полное скачивание EXE и SHA256.

## Проверки

```sh
npm test
npm run export:html
npm run test:e2e
```

Unit/integration проверяют ранжирование и музыкальный стиль поиска, 128 записей, курсоры волны, импорт/откат, порядок добавления, публичные метаданные и разрешения, серверные Range и границы редиректов. Браузерные сценарии покрывают настоящий HTMLAudioElement, списковый поиск, старые YouTube-записи без потери данных, очередь, 120 новых треков, 128 CSV-записей, офлайн Blob/перезагрузку/отмену скачивания, мобильный экран, фокус и автономный HTML. В воспроизводимом наборе внешние ответы подставные; проверки реального источника запускаются отдельно:

```sh
npm run test:wave:live
npm run test:playback:live
npm run test:electron:live
```

16 октября 2026 проверка настоящего Internet Archive получила 120 разных треков в десяти партиях с четырёх страниц и 65 536 байт MP3 с HTTP 206/CORS. Проверка настоящего приложения в Chromium через встроенный HTTP-сервер/CSP воспроизвела запись длительностью 256,61 с, проверила паузу/продолжение, перемотку на 20 с и сохранение избранного после перезагрузки. Подставных ответов, iframe и запросов к YouTube в ней не было. Это браузерная проверка, а не нативный запуск Windows.

Проверка `test:electron:live` запускает именно production-приложение Electron и использует настоящий `net.request`. 16 октября 2026 на Linux/Electron 44.7.2 воспроизведена прежняя ошибка `net.fetch`, проверены ручной редирект, Range, HEAD и отмена; затем через настоящий Archive воспроизведены Aydio XHD (295,37 с) и Step One из DWK031, пауза/продолжение, перемотка на 60 с и переключение трека. Windows EXE нативно не запускался.

Для проверки нужен установленный Electron (или `ELECTRON_PATH` к проверенному официальному runtime), графический дисплей Linux и свободный порт 28741. Профиль проверки временный; пользовательская коллекция не меняется. При наличии `HTTPS_PROXY` тест передаёт его Chromium. В облачной среде с собственным CA настрой доверие NSS штатным `certutil`, сохраняя проверку TLS; `ELECTRON_TEST_HOME` и `XDG_DATA_HOME` позволяют выбрать временный каталог тестовых сертификатов. Не используй отключение проверки сертификатов или изменение HOME. Это настройка только тестового процесса, в EXE она не добавляется.

Playwright использует `/usr/bin/chromium` (или `CHROMIUM_PATH`), порт 4173 и актуальный `dist`. Не пересобирай `dist` во время тестов или упаковки EXE.

## Основные файлы

- `src/App.tsx`, `src/AudioSearch.tsx`, `src/OpenLibrary.tsx` — экраны, списковый поиск, релизы и общий плеер.
- `src/openCatalog.ts`, `src/audioSource.ts`, `server/archive.mjs` — адаптер источника и серверная передача.
- `src/musicTaste.ts`, `src/recommendations.ts`, `src/useListening.ts`, `src/wave.ts`, `src/useWave.ts` — предпочтения, ранжирование и открытия.
- `src/library.ts`, `src/libraryImport.ts`, `src/offline.ts` — сохранение состава, импорт и офлайн-файлы.
- `desktop/main.mjs`, `desktop/network.mjs`, `server/app-server.mjs` — окно Windows, системная сеть и встроенный сервер.
- `scripts/build-sw.mjs`, `scripts/export-portable.mjs`, `scripts/package_release.py` — кэш, HTML и выпуск файлов.
